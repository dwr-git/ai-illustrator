# AI Вектор — установка на сервер

Векторный редактор в браузере (открывает файлы Illustrator .ai, а также SVG, PDF, EPS) со встроенным
помощником на вашей локальной модели и файлами на вашем сервере. Раньше назывался AI-Illustrator, а ещё раньше — AI-Corel.

Illustrator — товарный знак Adobe. AI Вектор не связан с Adobe и работает с файлами в её форматах.

На сервере нужны только **nginx + PHP + Ollama** — то, что у вас уже есть. Ничего компилировать не нужно.
Редактор полностью автономный: всё загружается из его папки, интернет и сторонние сайты не нужны.

## Установка (5 минут)

1. **Скачайте готовую сборку.** GitHub → репозиторий `ai-illustrator` → справа **Releases** →
   верхняя «Сборка N — дата» (с пометкой Latest) → файл `ai-illustrator-build-N-ГГГГ-ММ-ДД.zip`.
   У каждой сборки свой номер и описание «что нового» (то же — в `CHANGES.ru.md`).
   Какая сборка стоит у вас, видно в шапке панели помощника: «Модель: … · сборка N».
2. **Распакуйте** — внутри одна папка `ai-illustrator`.
3. **Положите её на сервер** рядом с остальными приложениями: `/app/src/ai-illustrator/`.
   Папку можно назвать как угодно и переименовать потом — все пути внутри относительные.
   Помощник сам найдёт ваш `auth.php` на два уровня выше (`/app/src/auth.php`)
   и через него — `config.php`, `.env`, адрес Ollama и модель.
4. **nginx** — помощнику нужны большие запросы (снимок экрана) и долгое ожидание модели:
   `client_max_body_size 20m;` и `fastcgi_read_timeout 200s;` для `api/assistant.php`
   (готовый пример — `nginx.conf.example`; правила в нём не зависят от имени папки).
   Для «Моих файлов» — блок `location ~ /api/files\.php$` с `client_max_body_size 512m;` из того же примера.
   Если у сервера эти значения уже больше (например, `client_max_body_size 999M` на весь сервер), ничего менять не нужно.
5. **Папка для файлов пользователей создаётся сама**: `storage/ai-illustrator` рядом с корнем сайта
   (`/app/storage/ai-illustrator` при корне `/app/src`). Проверка: `https://ваш-домен/ai-illustrator/api/files.php`
   → `{"ok":true,…}`.
6. **Откройте** `https://ваш-домен/ai-illustrator/` — войдите в систему, если ещё не вошли.
   Справа появится панель «Помощник».

Обновление — то же самое: скачать новый zip и заменить папку. Свой `studio/config.js`
перед заменой лучше сохранить.

## Что внутри папки

| Путь | Что это |
|---|---|
| `index.html` | Страница редактора |
| `app/` | Сам редактор (WebAssembly, сжат и разрезан на части) |
| `studio/loader.js` | Показывает ход загрузки и, если что-то не так, какой файл не пришёл и почему |
| `studio/` | Панель помощника: `studio.js`, `studio.css`, `ru-labels.json`, `version.json` |
| `studio/config.js` | **Настройки панели** — можно править прямо на сервере |
| `api/assistant.php` | Помощник: проверяет вход, отправляет запрос в Ollama |
| `api/files.php` | «Мои файлы»: документы каждого пользователя на сервере |
| `api/settings.php`, `api/tools.php` | Внутренние настройки и список действий помощника |

## Форматы

Открывает: SVG и SVGZ, PDF, AI, EPS, DXF, EMF/WMF, PSD, картинки (PNG, JPEG, WebP, GIF, TIFF), файлы Affinity.
Сохраняет и экспортирует: собственный формат, SVG, PDF, EPS, AI (совместимый с PDF), PNG, JPEG, WebP.
Файлы CorelDRAW (`.cdr`) редактор пока не открывает — сохраните их в CorelDRAW как SVG, PDF или EPS.

## Мои файлы

- **Ctrl+S** (и «Файл › Сохранить») сохраняет документ в «Мои файлы» на сервере — значок папки в
  шапке панели помощника. Первый раз спросит имя, дальше сохраняет туда же. «Сохранить как…» —
  под новым именем. В окне с именем есть и кнопка «На компьютер» — скачать вместо сервера.
- На сервер уходят документы: собственный формат (`.vectorcraft`, старые `.drawcraft`), SVG/SVGZ,
  PDF, AI, EPS — и при сохранении, и при экспорте в эти форматы. PNG, JPEG, WebP и прочее
  по-прежнему скачивается на компьютер.
- **Мои файлы**: список с датой и размером, поиск, открыть, переименовать, удалить (файл уходит в
  корзину `.trash` в папке пользователя), «Новый документ», «С компьютера…» (открыть файл с
  компьютера; на сервер он попадёт после Ctrl+S), «На компьютер» (скачать открытый документ).
- У каждого пользователя своя папка (`storage/ai-illustrator/u-<пользователь>`), имена файлов на
  диске случайные, список — в `index.json`.
- Если сохранить на сервер не удалось (нет связи, не вошли, файл больше лимита), файл сразу
  скачивается на компьютер, а копия остаётся в браузере: при следующем запуске панель предложит её
  открыть. Выключить «Мои файлы» — `files: ''` в `studio/config.js`.

## Настройки в `.env` (необязательно)

По умолчанию помощник берёт всё из вашей системы. Переопределить можно так:

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `AI_ILLUSTRATOR_MODEL` | Модель помощника (нужны картинки и tools) | `GLOBAL_MODEL` |
| `AI_ILLUSTRATOR_OLLAMA_URL` | Адрес Ollama или шлюза | `OLLAMA_IP:OLLAMA_PORT` |
| `AI_ILLUSTRATOR_CONTEXT` | Размер контекста | `GLOBAL_MODEL_CONTEXT` или 32768 |
| `AI_ILLUSTRATOR_TIMEOUT` | Сколько секунд ждать модель | 180 |
| `AI_ILLUSTRATOR_MAX_TOKENS` | Длина ответа | 2048 |
| `AI_ILLUSTRATOR_AUTH_FILE` | Путь к `auth.php`, если папка лежит не в `/app/src/` | ищется автоматически |
| `AI_ILLUSTRATOR_ALLOW_ANON` | `1` — без входа (только для проверки!) | выключено |
| `AI_ILLUSTRATOR_DATA_DIR` | Где хранить файлы пользователей | `storage/ai-illustrator` рядом с корнем сайта |

### Откуда помощник берёт модель

Главный источник — файл **.env** вашей системы. Помощник находит его сам: рядом с папкой приложения
и выше по папкам (обычно это `.env` в корне сайта или уровнем выше). Если .env лежит в другом месте,
укажите путь в переменной `AI_ENV_FILE`. Значения из .env важнее переменных окружения процесса:
если сервер запущен со старыми переменными, а .env поменяли, работает то, что написано в .env.

Порядок поиска (берётся первое найденное):

| Что | Где ищется |
|---|---|
| Адрес сервера модели | `AI_ILLUSTRATOR_LLM_URL` → `LLM_URL`, `OLLAMA_URL`, `OPENAI_BASE_URL` (берутся как есть); без них — первый, который отвечает, из: `OLLAMA_IP` + `OLLAMA_PORT`, `OLLAMA_HOST` (без порта — `OLLAMA_PORT` или 11434, как у самой Ollama), `$url_ollama` из config.php системы, `127.0.0.1:11434` |
| Модель | `AI_ILLUSTRATOR_MODEL` → `GLOBAL_MODEL`, `LLM_MODEL`, `OLLAMA_MODEL`, `CHAT_MODEL`, `DEFAULT_MODEL` → `$global_model` из config.php → первая модель, которую отдаёт сам сервер |
| Размер контекста | `AI_ILLUSTRATOR_CONTEXT` → `GLOBAL_MODEL_CONTEXT`, `LLM_CONTEXT`, `OLLAMA_CTXSIZE` → `$ollama_ctxsize` → 32768 |
| Ключ (если шлюз его требует) | `AI_ILLUSTRATOR_API_KEY` → `LLM_API_KEY`, `OPENAI_API_KEY` |
| Протокол | `AI_ILLUSTRATOR_LLM_API` или `LLM_API` = `ollama` / `openai`; без них определяется сам |

- **Любой сервер:** работает и с Ollama, и с OpenAI-совместимыми серверами (vLLM, GLM, LM Studio и
  другие). Адрес с `/v1` на конце считается OpenAI-совместимым. Если у адреса нет `/api/chat`
  (как у Ollama), помощник сам пробует `/v1/chat/completions`.
- **Любая модель:** имя модели сверяется со списком моделей сервера. Если такой модели там нет,
  берётся подходящая из списка. Если шлюз принимает имена-псевдонимы, которых нет в его списке
  (например `chat`), поставьте `LLM_MODEL_CHECK=0`.
- Если сервер не умеет вызывать инструменты, помощник сам переходит на текстовый протокол вызовов.
- **Как проверить:** наведите мышь на строку «Модель: …» в шапке панели помощника. Там написано,
  какая модель используется и из какой строки .env она взята. То же показывает адрес
  `api/assistant.php` в браузере.


Запросы помечаются для шлюза как `ai-illustrator` через ваш `enrichLLMPayload()`.

## Как работает помощник

- **Совет** — объясняет, где найти функцию и что выставить. Ничего не меняет.
- **Сделай** — сам рисует и меняет объекты: находит нужную команду, рисует фигуры и текст,
  красит, выравнивает, объединяет контуры, открывает диалоги и нажимает OK, смотрит на результат.
  Каждое действие видно в ленте, у каждого есть кнопка «Отменить»; всё отменяется и Ctrl+Z.
  Удаление, закрытие и сохранение — только после вашего «Разрешить».
- **Быстрая строка — Ctrl+Shift+Пробел** (или кнопка-молния в шапке панели): поле внизу над холстом,
  ответ всплывает над ним, вся история — в панели.
- **Глаз** рядом с полем ввода — показывать ли помощнику экран (снимок уходит только на ваш сервер).
- **Домик** справа в верхней строке редактора — на уровень вверх, на ваш сайт (`homeUrl` в `studio/config.js`).
  Слева, рядом с меню, — значок сетки: стартовый экран редактора со списком недавних файлов.
- **Палитра** рядом с домиком — список тем: Фирменная, Неоморфная светлая, Неоморфная тёмная, затем остальные.
  Панель помощника переключается вместе с редактором; выбор запоминается.
- Пока модель думает, сервер помощника раз в 10 секунд отправляет пустой пробел, чтобы роутер,
  VPN или прокси не оборвали «молчащее» соединение.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Редактор не запускается | Под полосой загрузки написано, какой файл не пришёл и почему. Чаще всего: папка скопирована не целиком, или правило сервера отдаёт вместо файлов другую страницу |
| После заливки по FTP — старая версия или «Не удалось скачать app/loader…» | Программа заливки пропустила файлы «того же размера» (так умеет FileZilla). С этой сборки размер таких файлов меняется в каждой сборке, но надёжнее в FileZilla выбрать для существующих файлов «Перезаписать», а не «Перезаписать, если размер отличается» |
| В панели «Нужно войти в систему» | Вход в вашу систему в этом же браузере и на этом же домене |
| «Не найден auth.php системы» | Задайте `AI_ILLUSTRATOR_AUTH_FILE` в `.env` |
| «Сервер помощника ответил не JSON» | PHP не обрабатывает `api/assistant.php` — проверьте блок PHP в nginx |
| Ошибка 413 | `client_max_body_size 20m` (пункт 4); при сохранении в «Мои файлы» — `client_max_body_size 512m` в блоке `api/files.php` и `post_max_size`/`upload_max_filesize` в PHP |
| «Не удалось создать папку для файлов» | Создайте `storage/ai-illustrator` и дайте PHP право записи, или задайте `AI_ILLUSTRATOR_DATA_DIR` |
| Ошибка 504 / ответ обрывается | `fastcgi_read_timeout 200s` (пункт 4) |
| «Сервер оборвал соединение» | Посмотрите `error.log` nginx в момент запроса |
| «Модель не умеет вызывать инструменты» | `AI_ILLUSTRATOR_MODEL` с поддержкой tools |
| «Модель не принимает картинки» | Выключите «глаз» или укажите мультимодальную модель |

Проверка помощника без панели: откройте `https://ваш-домен/ai-illustrator/api/assistant.php` —
должно показать `{"ok":true,"model":"…"}`.

## Для разработчика

- Сборку делает GitHub Actions (`.github/workflows/studio.yml`) на каждое изменение ветки `main`.
- Редактор управляется со страницы через `window.vectorcraft` (`apps/vectorcraft-web/src/api.rs`):
  `request(метод, параметры)`, `execute(команда, параметры)`, `commands()`, `inspect()`, `screenshot()`, `openFile(имя, байты)` —
  те же методы, что в `docs/control-protocol.md`. В консоли браузера: `await aiillustrator.call('ui.inspect')`.
- Панель: `studio/web/`, сервер помощника: `studio/api/`, сборка папки: `studio/build/package.sh`.
- Сохранение на сервер: страница ставит `vectorcraft.takesSaves = true`, и сохранения документов
  (`apps/vectorcraft-web/src/saved_files.rs` `is_document`) приходят событием `vectorcraft:save`
  {name, path, bytes} вместо скачивания → `api/files.php`.
